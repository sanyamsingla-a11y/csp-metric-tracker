## Key technical details

### Column layout
Earnings uses `D-1, D-2, D-3, W-1, W-2, W-3, M-1, M-2, M-3` (daily/weekly/monthly lookbacks) instead of the `Today, T-1..T-7` used by other workflows.

### Shared SQL pattern
All 8 health queries share the same CTE header:
```
params → anchors (as_of_date, current_week_monday, current_month_start) → periods (9 rows) → csp_account (filter test CSPs)
```
Then type-specific event CTEs, union into `all_events`, aggregate into `period_rates`, pivot to single row.

### Sub-table queries (Q9, Q10) use a different pattern
- `period_def` CTE with `CURRENT_DATE()` instead of `convert_timezone` params
- `carry_fee_test_ids` — 36 hardcoded UUIDs for test CARRY_FEE entries to exclude
- `t_txn_matched` — legacy bonus CSPs paid via DynamoDB t_transactions (RATING_INCENTIVE)
- Full outer joins between entitlement_ledger and wallet_ledger per entry type

### Key Snowflake schemas used
- `csp_compensation_service_csp_compensation_service` — entitlement_ledger_entries
- `csp_payment_settlement_service_csp_payment_settlement_service` — wallet_ledger_entries, deposit_ledger_entries, liability_ledger_entries, settlement_day_batch_entry, payout_retry_log
- `csp_asset_custody_service_csp_asset_custody_service` — outbox_record (recovery events)
- `csp_gateway_service_csp_gateway_service` — csp_account
- `prod_db.public.razorpayx` — RazorpayX payout status
- `DYNAMODB.T_TRANSACTIONS` — legacy bonus transactions
- `prod_db.clevertap_csp_api.events_data` — notification delivery (Q8)

### Fivetran filters
All queries use `_fivetran_active = TRUE` and/or `coalesce(_fivetran_deleted, false) = false` for history-mode tables.
